Referenz für die Übungs- & Lab-Aufgaben „Passwortwiederherstellung“. Deckt die Standard-Toolchain (hashcat, John, *2john) und die konkreten Angriffsstrategien für jeden Aufgabentyp ab. Bewertungslogik
Der Weg zählt, nicht nur der Fund. Für jede Aufgabe sprechfähig sein zu: Vorbereitung (Extraktion, Hash-Aufbereitung, Wörterbuch-Quellen, Tooling), Angriff (Schritte + gefundene Passwörter) und Dauer der Suche (grob in Minuten).

1. Analyse

Erst verifizieren, was man wirklich vor sich hat — Dateiendungen lügen (siehe Aufgabentyp „Numbers<X>“ unten).

file Unbekannt.dat
binwalk -E Unbekannt.dat        # Entropie — hoch & flach = verschlüsselt/komprimiert
xxd Unbekannt.dat | head        # Magic Bytes von Hand prüfen
Magic Bytes (hex)Typ
25 50 44 46 (%PDF)PDF
37 7A BC AF 27 1C7-Zip
50 4B 03 04 (PK)ZIP / DOCX / XLSX / ODT / Pages / Numbers / KeePass-Container-Varianten
03 D9 A2 9A / ASCII KDBXKeePass 2.x Datenbank
Gotcha
Viele moderne Formate (docx, odt, pages, numbers, kdbx-Export) sind intern ZIP-Container. file und binwalk erkennen trotzdem meist das konkrete Sub-Format — im Zweifel unzip -l versuchen (schlägt bei echter Verschlüsselung fehl, das ist selbst schon eine Information).

2. Hash-Extraktion — die *2john-Familie

Muster: <typ>2john <datei> > <datei>.john. Die Ausgabe ist John-Syntax (dateiname:$hash$...) und muss für hashcat meist bereinigt werden.

ToolFürhashcat -m
pdf2john.plVerschlüsselte PDFs10400/10410/10420 (Acrobat 2–4) · 10500 (Acrobat 5–8, RC4/AES-128) · 10600/10700 (Acrobat 9+, AES-128/256) — welcher Modus, verrät pdf2johns Ausgabe selbst (Revision/V-Wert)
7z2john.pl.7z-Archive11600
zip2john.zip-Archive17200 / 17210 / 17220 / 17225 / 17230 (PKZIP, je nach Kompression) · 13600 (WinZip/AES)
keepass2johnKeePass .kdbx13400
libreoffice2johnODF: .odt / .ods / .odp18400
iwork2johnApple iWork: .pages / .numbers / .key23300
office2john.pyMS Office: .docx/.xlsx/.pptx9500 (2010) / 9600 (2013+) · 9400 (2007)
dmg2johnVerschlüsselte macOS DMGs16400/16700 (je nach Verfahren) — sonst direkt mit John angreifen
# PDF: nur Dateinamen-Präfix (alles vor dem ersten ':') entfernen
pdf2john.pl Star.pdf | sed -E "s/^[^:]+://" > Star.pdf.hashcat

# LibreOffice: Präfix UND irrelevanten Suffix abschneiden
libreoffice2john Numbers1.odt | sed -E -e 's/[^:]+://' -e 's/:::::[^:]+$//' > Numbers1.odt.hashcat

# iWork (.pages / .numbers)
iwork2john Poem.pages > Poem.pages.john
sed -E "s/^[^:]+://" Poem.pages.john > Poem.pages.hashcat

# KeePass
keepass2john "Max Müller.kdbx" | sed -E "s/^[^:]+://" > MaxMueller.hashcat
Modus checken
Nie raten: hashcat --example-hashes bzw. das Hashcat-Wiki „Example Hashes“ zeigen exakt, wie ein gültiger Hash für den jeweiligen Modus aussehen muss — damit lässt sich die eigene sed-Bereinigung verifizieren, bevor man Zeit in einen Angriff steckt.

3. Hashcat Basics

hashcat -m <hash-modus> -a <angriffsmodus> <hashdatei> <angriffsquelle(n)> [optionen]
-O = optimierter Kernel (kürzere Passwörter, schneller) -w 3 = Workload „high“ --show = bereits geknackte anzeigen --status --potfile-path -force nur wenn nötig

Angriffsmodi (-a)

ModusNameBeschreibung
-a0WörterbuchWortliste testen, optional mit Regeln -r
-a1KombinationsangriffKreuzprodukt zweier Wörterbücher (z. B. Stadt+Stadt)
-a3Brute-Force / Maskealle Kandidaten gemäß Maske
-a6HybridWort + Maske (Wort zuerst)
-a7HybridMaske + Wort (Maske zuerst)

Masken & Zeichensätze

PlatzhalterZeichensatz
?la-z
?uA-Z

?a?l?u?d?s

Eigene Zeichensätze mit -1 … -4, referenziert als ?1…?4:

# Sonderzeichen-Klasse nur $, € und ! — Maske für 4 Stück davon am Ende
hashcat -m 10700 star.hashcat -a3 -1 '$€!' "?u?l?u?l?d?d?d?d?1?1?1?1"

hashcat -m 0 hash.md5 -a0 /usr/share/wordlists/rockyou.txt \
  -r /usr/share/hashcat/rules/best64.rule

# zwei Regelsätze = Kreuzprodukt
hashcat -m 1400 hash.sha256 candidates.txt -r number_prepend.rule -r sc_append.rule
Duplikate vermeiden
Im Kreuzprodukt keine redundanten Regeln erzeugen — $1: und :$1 liefern dasselbe Ergebnis, kosten aber doppelt Rechenzeit.

Wortlisten bauen (--stdout)

Hashcat kann Kandidaten nur ausgeben statt anzugreifen — nützlich, um Zwischenwörterbücher zu bauen (z. B. Stadt×Stadt-Kombinationen).

# Kreuzprodukt zweier Städtelisten, ohne Trenner
hashcat --stdout staedte.txt staedte.txt -j '$-' | tr -d '-' > staedte-kombiniert.txt
# → BerlinHamburg, BerlinMuenchen, ...

John the Ripper

Primär für Hash-Extraktion (*2john) sowie für Hash-Typen, die hashcat nicht kennt.

john hash.john --wordlist=/usr/share/wordlists/rockyou.txt --rules=best64
john --show hash.john          # geknackte anzeigen
john --format=Raw-SHA256 hash.txt   # Format erzwingen, falls Auto-Detect danebenliegt

Princeprocessor

Erzeugt aus Fragmenten einer Wortliste alle Kombinationen (PRINCE-Algorithmus) — extrem nützlich für OSINT-Wortlisten (Namen, Städte, Zahlen aus einem Profil), lässt sich direkt an hashcat pipen.

princeprocessor --pw-min=6 --pw-max=16 osint_fragmente.txt \
  | hashcat -m 13400 MaxMueller.hashcat -r number_prepend.rule -r sc_append.rule
ParameterWirkung
--pw-min / --pw-maxLänge der erzeugten Kandidaten
--elem-cnt-min/maxAnzahl Fragmente pro Kandidat
--keyspacenur Größe des Suchraums ausgeben
--case-permuteGroß/Klein des 1. Buchstabens permutieren

4. Verifikation & False Positives

Insbesondere bei OpenSSL enc
Ein Kandidat meldet „Erfolg", wenn das PKCS#7-Padding der letzten 1–16 Byte zufällig gültig ist — ohne dass der Klartext stimmt. Wahrscheinlichkeit eines Zufallstreffers ≈ 1/256 pro Kandidat → bei größeren Kandidatenlisten sind mehrere Scheintreffer normal.

Immer den entschlüsselten Inhalt prüfen (file auf die Ausgabe, erwartete Magic Bytes, lesbarer Text statt Binärmüll) — nicht nur den Exit-Code von openssl. Gleiches Prinzip bei Archiven/Containern ohne Integritätsprüfung: erst der erfolgreiche Entpack-/Mount-Vorgang zählt.
