0. Analyse

Warum? Viele Dateitypen trügen — ein .odt kann eine LibreOffice-ODF-Datei sein, eine Apple-Numbers-Datei oder etwas völlig anderes. Die Dateiendung allein sagt nichts über den internen Verschlüsselungsmechanismus aus. Das Bestimmung des korrekten Dateityps ist der wichtigste Schritt, weil er den Hash-Modus (-m) und das Extraktionstool vorgibt. Ein falscher Modus verschwendet Rechenzeit oder scheitert komplett.

Was macht file? Es liest die ersten Bytes (Magic Bytes) der Datei und vergleicht sie mit einer Datenbank bekannter Signaturen — unabhängig von der Dateiendung. Was macht binwalk -E? Es berechnet die Entropie in 8-Byte-Blöcken und erzeugt ein ASCII-Art-Diagramm: hohe, gleichmäßige Entropie (~8.0 Bits/Byte) bedeutet, dass die Daten verschlüsselt oder komprimiert sind (kein Muster erkennbar). Niedrige/schwankende Entropie deutet auf Klartext oder teilstrukturierte Daten hin. Was macht xxd? Zeigt den hexadezimalen Byte-Inhalt an — damit kann man Magic Bytes manuell prüfen, wenn file keinen klaren Treffer liefert.

file Unbekannt.dat
binwalk -E Unbekannt.dat        # Entropie — hoch & flach = verschlüsselt/komprimiert
xxd Unbekannt.dat | head        # Magic Bytes von Hand prüfen

1. John the Ripper — Hash-Extraktion

Muster: <typ>2john <datei> > <datei>.john. Aufklappen für ein Beispiel an einer der Aufgaben-Dateien.

Sed-Workflow: John-Hash → Hashcat-Format

Die *2john-Ausgabe ist John-Syntax (dateiname:$hash$...[:zusatz]). Für hashcat muss man den Hash isolieren — die meisten Tools liefern mehr. Dein Standardworkflow:

Step 1

John extrahieren

*2john Datei > name.hash
Original-Hash sichern — nie überschreiben, falls John parallel gebraucht wird.

Step 2

Sed bereinigen

sed ... name.hash > name.hashcat
Hash-String für hashcat isolieren — Präfix und ggf. Suffix entfernen.

Step 3

Hashcat angreifen

hashcat -m <modus> name.hashcat ...
Die bereinigte Datei wird als Input übergeben.

# Standardfall: nur Präfix (alles vor dem ersten ':') entfernen — reicht für die meisten Formate
pdf2john.pl Star.pdf > star.john          # Schritt 1: John-Extrakt
sed -E "s/^[^:]+://" star.john > star.hashcat   # Schritt 2: für hashcat aufbereiten
# hashcat -m 10700 star.hashcat -a3 ...         # Schritt 3: Angriff

# LibreOffice/ODF: zusätzlich den irrelevanten Suffix abschneiden
#   Das Suffix (:::::Typname) nach dem Hash ist für hashcat irrelevant.
#   Prüfsumme via -e separates Script entfernen:
libreoffice2john Numbers1.odt | sed -E -e 's/[^:]+://' -e 's/:::::[^:]+$//' > Numbers1.hashcat

# KeePass (.kdbx): sed -E "s/^[^:]+://" reicht — Hash-Payload nach dem ersten ':'

# 7-Zip: sed -E "s/^[^:]+://" — Hash-Payload nach dem ersten ':'

# Allgemeine Merkregel:
#   - Hashcat braucht NUR den Hash-String (alles nach dem ersten ':')
#   - John braucht den vollen Output (mit Dateinamen)
#   - Die .john-Datei immer behalten — für John-Angriffe oder Debugging
Format verifizieren
Vor dem Angriff hashcat --example-hashes bzw. das Hashcat-Wiki „Example Hashes" gegen den eigenen bereinigten Hash halten — spart Zeit, die man sonst in einen falsch formatierten Angriff steckt.

2. Hashcat — Grundsyntax

hashcat -m <hash-modus> -a <angriffsmodus> <hashdatei> <angriffsquelle(n)> [optionen]

Was ist was: -m legt fest, wie hashcat den Hash interpretiert (MD5 = 0, SHA-256 = 1400, 7z = 11600, etc.). -a bestimmt die Angriffsmethode (Wörterbuch, Brute-Force, Hybrid, Kombination). Die Hashdatei enthält den zu knackenden Hash (zeilenweise). Angriffsquellen sind Wortlisten, Masken oder Sprachregeln.
